# DC-001 — a write decided on a stale base could be published over newer remote history

- **Found by:** independent engine test owner (tests/App.Engine.Tests), before the first release candidate.
- **Severity:** critical (silent loss of another writer's events; violates CONTRACT §9.4.2 and EXT-DATA-006).
- **Manifestations (original reproductions, kept as tests):**
  1. `9d` — after a rebase over another writer, a later write to the investigation that writer changed erased it.
  2. `10b` — retry of a held change after a reload overwrote a concurrent change to the same investigation.
  3. `11d` — an applied write whose outcome was unknown, with the branch moved on, was reported as "not written".
- **Root cause:** publications were parented by the session's *current* head, which could move (rebase, reload)
  without the decision's input state being re-read; a fast-forward then hid the overwrite. Reconcile compared refs
  for equality instead of ancestry.
- **Class-level fix (5675d7c):** every publication is built on and parented by the exact commit its decision was read
  at (`Write.BaseCommit/BaseTree`); any intervening change therefore forces the non-fast-forward path, where the
  investigation's files are compared before any rebase. The catalog read point (`Live.Head`) moves only on a
  consistent re-read or a verified write parented by it; otherwise the catalog is re-read. Unknown outcomes are
  reconciled by ancestry (`GET compare/{ours}...{head}`).
- **Proof:** 3 original reproductions + 27 adversarial flow tests green; independent security review requested.
