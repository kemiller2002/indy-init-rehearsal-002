# DC-003 — failures after the ref update was sent were reported as definite

- **Found by:** independent security/adversarial review (finding F2, medium; F4 low).
- **Severity:** medium (the user was told "not saved" and offered Retry for a change that may already be on GitHub;
  retrying then raced the applied write).
- **Root cause:** failure classification ignored the write stage. Once `PATCH /git/refs` has been sent, a network
  error, a cancelled request or a read-back mismatch cannot prove the branch did not move.
- **Class-level fix:** `Shell.onWrite` classifies failures by stage: at or after `UpdatingRef` every failure is
  `Unknown` (reconcile only, no Retry); a cancelled request is `OutcomeUnknown`, not `Offline`; a read-back that does
  not match is `Unknown`. Reconciliation never sends a PATCH with an empty sha: if no commit was created it publishes
  again from the blobs.
- **Proof:** tests `11c` (updated expectation), `16`.

Related lows fixed in the same change: F5 (blob size cap 4 MiB → `R002.FILE_TOO_LARGE`; duplicate directory names
refused; truncation surfaced), F6 (repository identity `full_name` must equal the requested owner/repo — test `17`),
F7 (site build starts from a clean WASM output, ships no PDBs), F8 (permanently mounted polite and assertive live
regions; critical news is assertive), F9 (`auth.renew` replaces a refused credential in memory and republishes the
held change — test `18`).

## Closure review (evidence/quality/closure-review-DC-002-004.md)

The independent reviewer found P1 (high, release-blocking): reconciling an Unknown hold whose blob creation never
completed, after the branch moved, threw `KeyNotFoundException` inside `Shell.handle` (the rebase path built a tree
from missing blob shas). The rebase now restarts at blob creation when any blob sha is missing. Lows fixed with it:
an Unknown hold accepts a renewed credential and reconciles with it; a network failure after a commit was created is
no longer described as "nothing was sent"; a rate-limited 403 (P4, filed under DC-004) is a retryable hold.
Regression tests `20` and `20d` fail on the earlier engine and pass now.

## Second closure review (evidence/quality/closure-review-2.md)

Residual D (low): a rebase kept the pre-rebase commit, so reconciling a lost commit creation re-sent a PATCH GitHub
had already refused. The rebase now clears the commit. Test `22c` fails on the earlier engine.
