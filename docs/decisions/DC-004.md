# DC-004 — write access was inferred from a field GitHub does not always report

- **Found by:** the live acceptance run against the real GitHub provider (causa-data Actions run 39964244367, L4).
  The mocked suites could not find it: the fake always reported `permissions`.
- **Severity:** high for the release (writing was impossible with GitHub App installation tokens, including the
  Actions `GITHUB_TOKEN`; the workspace showed "read-only" and L4 timed out).
- **Root cause:** `permissions.push` is the *user's repository role*. GitHub omits `permissions` for installation
  tokens, and for fine-grained tokens the role says nothing about the token's own scope. A missing field was read
  as `false`.
- **Class-level fix:** `Access.CanPush` is `bool option` and advisory. Only an explicit `false` disables writing;
  an absent role offers saving and GitHub decides, with a refused write held as `WriteDenied` (renewable, F9).
  The status names the case ("write not reported").
- **Proof:** test `17b` (a repository answer without a role still creates and verifies); live L4 re-run.
- **Defect class lesson:** provider fields are claims with provenance; absence is not denial. Every live-provider
  assumption needs a test whose fake can omit the field.

## Second live finding (causa-data run 39972716429, build 5388739)

The first fix treated only an *absent* role as unknown. The live run showed GitHub answers the Actions installation
token with `permissions.push: false`, yet that token can write. The role therefore cannot gate writing in either
direction. It is now advisory only: saving is always offered on a writable workspace, the status reads "write may
be refused", and GitHub's answer to the write decides (a refusal is held as WriteDenied, renewable, never lost).
Tests `17c` (push false, write succeeds) and `17d` (GitHub refuses, change held and renewable); the browser test for a
read-only role now asserts the advisory behaviour. The same run found that the renewal controls never rendered:
a `data-if` template keeps one root element, so the token field and button are now wrapped in one container.
