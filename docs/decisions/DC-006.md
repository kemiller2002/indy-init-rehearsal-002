# DC-006 — a framework file failing mid-boot left the page loading until the 90 s timeout

- **Found by:** deployed acceptance on main 3eb7995 (run 39983316689). Right after the Pages deploy, the CDN
  answered 503 for one framework file (`System.ComponentModel.EventBasedAsync…wasm`); its body failed the
  integrity check and the .NET loader rejected internally.
- **Severity:** medium (no data at risk, but a user saw a spinner for up to 90 s instead of the recoverable failure;
  violates WASM-LOAD-005's prompt failure and recovery).
- **Root cause:** the loader downloads framework files in parallel and reports a failed one only as an unhandled
  rejection; the kernel's start promise never settles, so only the timeout ended the wait.
- **Fix:** while starting, any unhandled rejection ends the start immediately with the recoverable failure and a
  focused Retry (`src/kernel/main.js`). Browser test "a 503 on one framework .wasm shows the recoverable failure;
  Retry reloads to ready" (fails on the earlier kernel: no state within 90 s).
- **Not fixed here:** the CDN serving a 503 during deploy propagation is GitHub Pages behaviour. Deployed acceptance
  will be re-run on the next deployment.
